# T2: Cross-platform plugin auto-update tool
*Created: 2026-08-12 14:20:00 IST*
*Last Updated: 2026-08-12 15:13:44 IST*

**Description**: Add a cross-platform updater that checks stable or rolling development releases, stages direct plugin assets, validates plugin identity, installs transactionally, and supports rollback without reading or writing secret data.
**Status**: 🔄 In Progress
**Priority**: HIGH
**Started**: 2026-08-12
**Dependencies**: T1

## Completion Criteria
- [x] Stable and development release checks are implemented.
- [x] Development checks can compare the embedded local commit hash with GitHub `main`.
- [x] Direct HTTPS assets and manifest plugin identity are validated before installation.
- [x] Partial writes automatically roll back to the pre-update runtime files.
- [x] Focused tests cover check, download, validation, and rollback behavior.
- [x] pnpm-based GitHub Actions workflow builds and publishes rolling `dev` releases and stable version-tag releases.
- [x] Release archives and SHA-256 checksum manifests are generated.
- [x] Obsidian plugin settings persist stable/dev channel choice and optional startup checks.
- [ ] Confirmation UI, reload, and real Android installation are verified.
- [ ] Artifact signature or trusted checksum verification is enforced by the updater before unattended installation.

## Notes
- The updater receives only the host request and vault-adapter interfaces; it never receives passwords, plaintext, ciphertext, or session keys.
- Startup checks are now optional and persisted in plugin settings; automatic installation and reload remain disabled until their explicit confirmation flow is implemented.
- The current settings integration checks the selected channel and never installs or reloads automatically.
- The current design follows the proven `obsidian-git` direct-artifact and rollback pattern, with HTTPS asset validation and no error logging of response bodies.
