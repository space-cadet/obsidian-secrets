## Notes
- The updater receives only the host request and vault-adapter interfaces; it never receives passwords, plaintext, ciphertext, or session keys.
- Startup checks are now optional and persisted in plugin settings; they report available updates without installing or reloading.
- Manual checks from native settings, the sidebar, or the command palette open an explicit confirmation modal before downloading, installing, and reloading.
- The current design follows the proven `obsidian-git` direct-artifact and rollback pattern, with HTTPS asset validation and no error logging of response bodies.
- CHECKSUMS.txt is generated by the build script and uploaded as a release asset. The updater downloads it and verifies SHA-256 of each plugin file before installation. A missing or mismatched checksum aborts the install and cleans up the temporary directory.
